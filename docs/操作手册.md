# 双相机视觉伺服：从硬件装配到闭环

本文命令均在 Jetson 执行。默认路径 `/home/jetson/fairino_ws/Vservo_ros2`。Web 操作和本次 ETH 超限复测见 [Web 操作台](Web操作台.md)。
每个新终端先执行：

```bash
source /opt/ros/humble/setup.bash
cd /home/jetson/fairino_ws/Vservo_ros2
source install/setup.bash
export ROS_DOMAIN_ID=99
export WS=/home/jetson/fairino_ws/Vservo_ros2
mkdir -p "$WS/data/calibration" "$WS/data/sessions" "$WS/data/reports"
```

## 1. 硬件如何安装

| 硬件 | 安装与作用 | 当前序列号 |
|---|---|---|
| FR5 | 基座固定于刚性台面，定义 `base`；姿态使用 tool0 法兰，软件不混用 TCP | 控制器默认 192.168.58.2 |
| Gemini 305 EIH | 刚性支架固定在末端法兰侧，镜头朝作业区；避开夹爪与工具遮挡 | CV27864000EE |
| Gemini 335 ETH | 固定在机架/台面外部，俯视或斜视完整作业区；不随机器人运动 | CP08863000Z7 |
| 标定板 | 7×5 ChArUco，格长15 mm、码长11 mm、DICT_4X4_50；平整哑光硬板 | 必须实测印刷尺寸 |

USB 3 分别接稳定接口，注意带宽与供电。EIH 电缆留足全部姿态的弯曲余量，固定应力释放点，
不绕关节、不拉扯插头。两路可独立采集，当前没有硬件曝光同步。
335 应能看到大范围目标，并与305近距离视野存在重叠；不要只覆盖机器人后方。
相机支架、镜头、焦距、分辨率、板尺寸、法兰工具或安装位置改变后，重做受影响的标定。

生成板图：

```bash
ros2 run vservo_ros2 tools board --out "$WS/data/charuco.png"
```

打印图像有效棋盘区域应为105×75 mm，不含外侧空白。按100%尺寸打印，关闭适应页面，用尺量格长。
如果使用其他尺寸，修改 `src/vservo_ros2/config/board.yaml`，所有标定和检测使用同一文件。
大场景中小板可能只有几像素；可使用更大的同规格比例板，但要改真实米制尺寸并重标定，不能混用两块不同尺寸。

**两类手眼的板固定方式完全不同：**

```text
EIH 阶段：base ── 固定标定板；base ── 机器人 ── flange ── EIH相机
ETH 阶段：base ── ETH相机；base ── 机器人 ── flange ── 固定标定板
作业阶段：base ── 工作目标；305与335观察同一个目标和同一套目标坐标轴
```

EIH：标定板固定在台面/基座侧，全程不能移动；拖动机器人带相机观察它。
ETH：把板牢固安装到末端法兰/夹具，板相对法兰全程不动；拖动机器人，让固定335观察板。
建议分阶段采集；把板从台面搬到末端后，不可继续追加到EIH会话。
无需事先知道板到基座或板到法兰的精确变换；求解会利用其“恒定不变”这一约束。

## 2. 构建与检查双相机

```bash
colcon build --symlink-install --packages-select vservo_ros2
source install/setup.bash
ros2 launch vservo_ros2 dual_camera.launch.py
```

此入口只开相机，不连接机器人。先关闭旧工程的 camera_preview/main_pbvs 等占用相机的进程。
在其他终端检查：

```bash
ros2 topic hz /eih/image_raw
ros2 topic hz /eth/image_raw
ros2 topic echo /eih/metadata --once --qos-durability transient_local
ros2 topic echo /eth/metadata --once --qos-durability transient_local
```

可用 `rqt_image_view` 查看 `/eih/image_raw`、`/eth/image_raw`。
默认640×480@30；按实际序列号传入 `eih_serial:=... eth_serial:=...`。
首次使用SDK出厂内参，仅供采集启动。它不会被当作“已验证”精度内参。

## 3. 两台相机分别做内参

相机保持工作时的分辨率与对焦。板在图像中心、四角、四边、远近和不同倾角出现；
建议25–40张，最少16张，覆盖每个方向，避免始终正对和仅围绕中心旋转。
固定曝光/照明，停稳后保存；角点应清晰、没有运动模糊或反光。
不要依赖打印板尺寸错误后得到的低像素残差判断尺度准确。

保持双相机入口运行，在另一终端启动305内参采集：

```bash
ros2 launch vservo_ros2 calibration.launch.py role:=eih mode:=intrinsic \
session_dir:="$WS/data/sessions/eih_intr_train" \
output:="$WS/data/calibration/eih_intrinsics.json"
```

每摆好一个姿态，执行一次：

```bash
ros2 service call /eih/calibration/capture std_srvs/srv/Trigger '{}'
```

不足角点、陈旧图像、重复同一帧会被拒绝。会话保存原图、角点、板规格及相机身份。
采够后执行：

```bash
ros2 service call /eih/calibration/solve std_srvs/srv/Trigger '{}'
```

确认 `success: true`。求解以每第4张为留出样本，不参加拟合，默认训练RMS及所有留出图像RMS均≤1px。
求解失败保留数据，不覆盖已有结果。停止该采集节点，335使用：

```bash
ros2 launch vservo_ros2 calibration.launch.py role:=eth mode:=intrinsic \
  session_dir:="$WS/data/sessions/eth_intr_train" \
  output:="$WS/data/calibration/eth_intrinsics.json"
```

保持采集节点运行。另开 ROS 终端，每换一个板姿态执行一次采集。

```bash
ros2 service call /eth/calibration/capture std_srvs/srv/Trigger '{}'
```

采齐 16 张或以上后，在该 ROS 终端执行求解。

```bash
ros2 service call /eth/calibration/solve std_srvs/srv/Trigger '{}'
```

会话目录必须是新目录，重做时使用新的名称；每条命令均等待相应节点启动后再执行。
在双相机启动终端按 Ctrl+C，随后用新内参重启。

```bash
ros2 launch vservo_ros2 dual_camera.launch.py \
  eih_intrinsics:="$WS/data/calibration/eih_intrinsics.json" \
  eth_intrinsics:="$WS/data/calibration/eth_intrinsics.json"
```

此时相机元数据应为 `source: charuco_calibrated`、`validated: true`，不是 factory_sdk。

## 4. 只读连接机器人，发布法兰 TF

机器人需在线，现场人员用示教器拖动/点动采样；本工程采集节点不会自动移动机器人。
另开终端：

```bash
ros2 run vservo_ros2 robot_bridge --ros-args -p execute:=false
```

读取关节角（SDK度→ROS弧度），使用原工程FR5 MDH模型算 `base_T_flange`，发布 `/tf` 和关节状态。
此阶段不用手眼文件，不发布相机外参。对照示教器tool0验证法兰位置和姿态，尤其是零点与基座轴向。
若机器人型号、运动学参数或控制器补偿与模型不一致，先修正；错误FK会直接污染手眼结果。
本版面向FR5，不能直接把其他FR型号套用。

## 5. EIH 手眼（305在法兰、板在台面）

按第1节固定EIH板；确认内参节点已退出且相机使用新内参。

```bash
ros2 launch vservo_ros2 calibration.launch.py role:=eih mode:=handeye \
  session_dir:="$WS/data/sessions/eih_handeye_train" \
  output:="$WS/data/calibration/eih_handeye.json"
```

在至少两个独立旋转轴上改变相机朝向，俯仰/偏航/滚转尽可能覆盖±20–40°，配合空间平移。
每次停稳等待≥1秒，执行：

```bash
ros2 service call /eih/calibration/capture std_srvs/srv/Trigger '{}'
```

建议25–40组，最少16组。每组同时记录该图像时刻的相机到板位姿与TF法兰位姿。
程序检查前0.5秒的法兰变化≤1mm/0.3°、检测质量、重复姿态与时间戳。
这只是静止检查，不能替代现场确认；板被手碰动不会由机器人静止检查发现。

```bash
ros2 service call /eih/calibration/solve std_srvs/srv/Trigger '{}'
```

输出 `flange_T_eih_camera`（JSON `matrix`，父 `flange`、子 `eih_optical_frame`）。
约束：`base_T_flange[i] × flange_T_camera × camera_T_board[i] = 固定 base_T_board`。
采用OpenCV PARK，检查旋转激励以及训练/留出不变量误差；默认最大10mm/2°只是初始质量门槛，
不表示已达到毫米级定位精度，应按作业要求收紧。

## 6. ETH 手眼（335固定、板在法兰）

停止EIH采集。将板刚性固定到法兰侧，确保相机和电缆不遮挡335视野。
335和基座均不能移动；板与法兰相对关系不能变化。

```bash
ros2 launch vservo_ros2 calibration.launch.py role:=eth mode:=handeye \
  session_dir:="$WS/data/sessions/eth_handeye_train" \
  output:="$WS/data/calibration/eth_handeye.json"
```

保持采集节点运行。每换一个机器人姿态并停稳至少 1 秒，在另一 ROS 终端执行一次采集。

```bash
ros2 service call /eth/calibration/capture std_srvs/srv/Trigger '{}'
```

采齐 16 组或以上后，在调用采集服务的终端执行求解。

```bash
ros2 service call /eth/calibration/solve std_srvs/srv/Trigger '{}'
```

输出 `base_T_eth_camera`；约束：
`inverse(base_T_flange[i]) × base_T_camera × camera_T_board[i] = 固定 flange_T_board`。
实现将机器人位姿取逆后送入同一手眼求解器，不能直接复用EIH矩阵方向。
EIH与ETH的数据集、输出文件独立，板的两种固定方式不可混采。

## 7. 独立验证内参、手眼、定位精度

### 7.1 EIH 内参独立验证（命令行）

1. 从已求解的 EIH 内参文件开始。保持双相机在线，准备新的板位置和倾角。去旧采集节点的启动终端按 Ctrl+C。
2. 在 Jetson 终端 C 启动新采集会话。记下命令打印的会话名。

   ```bash
   source /opt/ros/humble/setup.bash
   cd /home/jetson/fairino_ws/Vservo_ros2
   source install/setup.bash
   export ROS_DOMAIN_ID=99
   mkdir -p "$PWD/data/sessions"
   SESSION=$(mktemp -d "$PWD/data/sessions/eih_intrinsic_cli_check_XXXXXXXX")
   basename "$SESSION"
   ros2 launch vservo_ros2 calibration.launch.py role:=eih mode:=intrinsic \
     session_dir:="$SESSION" output:="$SESSION/unused.json" protect_output:=true
   ```

3. 保持终端 C 运行。每次摆好新的板姿态并确认画面清晰。在 Jetson 终端 D 运行采集命令，每个姿态执行一次。至少取得 5 个成功样本。

   ```bash
   source /opt/ros/humble/setup.bash
   cd /home/jetson/fairino_ws/Vservo_ros2
   source install/setup.bash
   export ROS_DOMAIN_ID=99
   ros2 service call /eih/calibration/capture std_srvs/srv/Trigger '{}'
   ```

4. 去终端 C 按 Ctrl+C。回终端 D 执行以下验证命令，输入前面打印的会话名和待验证 JSON 路径。可直接回车使用本角色的默认路径，若求解结果在会话目录，输入其完整路径。

   ```bash
   read -r -p 'EIH 内参验证会话名: ' SESSION
   read -r -p 'EIH 内参文件路径（回车使用 data/calibration/eih_intrinsics.json）: ' CALIBRATION
   CALIBRATION=${CALIBRATION:-"$PWD/data/calibration/eih_intrinsics.json"}
   REPORT="$PWD/data/reports/$SESSION.json"
   mkdir -p "$PWD/data/reports"
   rc=0
   bash scripts/test_intrinsics.sh "$PWD/data/sessions/$SESSION/samples.json" \
     "$CALIBRATION" "$REPORT" || rc=$?
   printf '%s\n' "$rc" > "${REPORT%.json}.exit"
   printf '退出码 %s\n' "$rc"
   if test -f "$REPORT"; then python3 -m json.tool "$REPORT"; fi
   ```

   退出码 0 为通过，2 为误差超门槛，1 为输入、配置或计算错误。内参验证使用默认 1 px 门槛检查单帧重投影误差。该命令行会话的报告可在 Web 查看。如果需要 Web 总览自动关联，使用页面创建独立验证会话。

### 7.5 定位精度

从两路手眼独立验证均通过开始。把目标固定在作业台。如果此前独立启动了相机、采集节点或机器人桥，先去各自终端按 Ctrl+C。以下命令使用 `data/calibration/` 下的文件。标定文件保存在 Web 会话目录时，从总览复制「启动完整只读伺服」命令。

```bash
source /opt/ros/humble/setup.bash
cd /home/jetson/fairino_ws/Vservo_ros2
source install/setup.bash
export ROS_DOMAIN_ID=99
ros2 launch vservo_ros2 visual_servo.launch.py execute:=false \
  eih_intrinsics:="$PWD/data/calibration/eih_intrinsics.json" \
  eth_intrinsics:="$PWD/data/calibration/eth_intrinsics.json" \
  eih_handeye:="$PWD/data/calibration/eih_handeye.json" \
  eth_handeye:="$PWD/data/calibration/eth_handeye.json"
```

在基座坐标系用独立量具/测量系统确定同一板原点及方向，保存：

```json
{"base_T_target": [[1,0,0,0.3],[0,1,0,0.1],[0,0,1,0.2],[0,0,0,1]]}
```

上例仅演示格式，必须替换成实际测量。不能用同一套视觉/手眼的输出充当地面真值。
将实测结果存到 `data/reference_point1.json`。每个位置使用自己的参考和输出文件，记录量具不确定度。

在 Jetson 另开终端 C 启动精度记录器。选择 FINE 时等待「双画面监控」显示精定位。

```bash
source /opt/ros/humble/setup.bash
cd /home/jetson/fairino_ws/Vservo_ros2
source install/setup.bash
export ROS_DOMAIN_ID=99
ros2 run vservo_ros2 accuracy_recorder --ros-args \
  -p output:="$PWD/data/accuracy_point1_fine.json" \
  -p reference:="$PWD/data/reference_point1.json" -p state_filter:=FINE
```

在 Jetson 终端 D 执行采集命令，每次收到新帧后再执行一次。至少 5 组，建议 30 组。

```bash
source /opt/ros/humble/setup.bash
cd /home/jetson/fairino_ws/Vservo_ros2
source install/setup.bash
export ROS_DOMAIN_ID=99
ros2 service call /accuracy_recorder/capture std_srvs/srv/Trigger '{}'
```

采够后去终端 C 按 Ctrl+C。回终端 D 生成报告。

```bash
mkdir -p data/reports
bash scripts/test_accuracy.sh "$PWD/data/accuracy_point1_fine.json" \
  "$PWD/data/reports/accuracy_point1_fine.json" 5 2
python3 -m json.tool data/reports/accuracy_point1_fine.json
```

测同一位置的 COARSE 时，保持只读伺服和参考目标在线。等 Web 显示 `COARSE`，在 Jetson 终端 C 启动粗定位记录器。

```bash
source /opt/ros/humble/setup.bash

source install/setup.bash
export ROS_DOMAIN_ID=99
ros2 run vservo_ros2 accuracy_recorder --ros-args \
  -p output:="$PWD/data/accuracy_point1_coarse.json" \
  -p reference:="$PWD/data/reference_point1.json" -p state_filter:=COARSE
```

在 Jetson 终端 D 执行下面的采集命令，每个新帧调用一次，至少 5 组。

```bash

source install/setup.bash
export ROS_DOMAIN_ID=99
ros2 service call /accuracy_recorder/capture std_srvs/srv/Trigger '{}'
```

采齐后去终端 C 按 Ctrl+C。回终端 D 生成粗定位报告。

```bash
mkdir -p data/reports
bash scripts/test_accuracy.sh "$PWD/data/accuracy_point1_coarse.json" \
  "$PWD/data/reports/accuracy_point1_coarse.json" 5 2

```

两个 JSON 分别保存 COARSE 和 FINE 样本及采样状态。
报告含平移mm、旋转deg的均值/RMS/P95/最大值。省略reference时，仅报告固定目标重复性，

## 8. 只读检查粗定位 → 精定位 → 伺服目标

移除ETH手眼阶段的法兰标定板，工作目标固定到台面。确保两路看到的是同一目标和坐标轴。
先关闭前面单独运行的相机、标定和robot_bridge，避免相机/RPC重复占用。

```bash
ros2 launch vservo_ros2 visual_servo.launch.py \
  eih_intrinsics:="$WS/data/calibration/eih_intrinsics.json" \
  eth_intrinsics:="$WS/data/calibration/eth_intrinsics.json" \
  eih_handeye:="$WS/data/calibration/eih_handeye.json" \
  eth_handeye:="$WS/data/calibration/eth_handeye.json"
```

默认 `execute:=false`，不会调用ServoMoveStart/ServoJ。

```bash
ros2 topic echo /localization/state
ros2 topic echo /localization/target_pose
ros2 topic echo /servo/status
ros2 topic echo /servo/next_flange_pose
ros2 topic echo /robot/status
```

当前采用首次可见相机主导策略。先看到目标的相机保持主导，失效时交给另一台仍有目标的相机。ETH 主导时为 COARSE，EIH 主导时为 FINE，两种来源都将法兰中心引向距标记 0.30 m 的期望位姿。有效观测时限为 0.30 s，双路偏差用于辅助观察。

Web 启动监控默认开启持续伺服。双路均失效后进入 HOLD，默认 0.5 s 后复位至 `[90, -110, 110, -180, -90, 0]` 度，完成后等待新目标并自动恢复。倍率范围 10%–100%，关节上限 2 rad/s。人工停止撤销持续请求，硬件、通信或越界故障进入故障停止。 [当前操作流程](Web操作台.md#2026-11-23-当前持续伺服逻辑)

相机坐标为x右、y下、z向前。ChArUco板平面z=0、+z穿入板面；
当前配置跟随法兰中心，在标记坐标 `[0,0,-distance]` 悬停，法兰 +Z 指向目标。ArUco ID42 原点为标记中心。原相机参考模式可通过 `tracking_frame: camera` 选择，法兰位姿由 `base_T_target × target_T_camera × inverse(flange_T_camera)` 得到。实际夹爪或剪切 TCP 需要单独标定工具偏置。

## 9. 现场执行闭环（需现场人员确认）

先完成前述独立测试并检查设备急停、速度、线缆、TCP、障碍物和有效工作空间。
编辑 `config/control.yaml` 或传入新 `control_config`；默认workspace仅为示例，不能覆盖实际碰撞风险。
确认目标、相机、机器人坐标系和原点方向正确，先在无接触且有足够余量的工位测试。
本次开发验证不会执行该步骤。

用第8节命令增加 `execute:=true hardware_ready:=true` 重启。仍处于DISARMED。
待定位稳定、有效微步命令出现且现场准备完毕，再执行：

```bash
ros2 service call /robot_bridge/arm std_srvs/srv/SetBool '{data: true}'
```

机器人桥以100Hz读取状态并ServoJ，IK在收到50Hz微步目标时求解。
每次任务空间目标变化≤1mm/0.01rad；桥接另检查5mm/3°最大微步、IK残差、分支跳变、
关节限位3°裕度、速度0.15rad/s、加速度0.3rad/s²和工作空间。
图像超时0.3秒、命令接收超时0.12秒、控制间隔>50ms或SDK失败时退出伺服并解除使能，必须显式重新arm。
Linux Python/RPC不是硬实时控制器，需用现场时序测量判断可用性；没有碰撞检测或轨迹避障保证。

正常停止：

```bash
ros2 service call /robot_bridge/arm std_srvs/srv/SetBool '{data: false}'
```

随后Ctrl-C退出。不会自动回位；解除软件使能不代替实体急停。任何危险情况使用机器人急停。

## 10. 常见问题

| 现象 | 排查 |
|---|---|
| 找不到相机 | 停止旧进程，检查USB3/udev/序列号/供电；不同型号不靠枚举顺序分配角色 |
| 话题不可见 | 所有终端source同一Humble与install，ROS_DOMAIN_ID一致 |
| 手眼采集拒绝 | 新内参是否validated、TF是否连续、停稳≥1秒、8个以上角点、姿态不要重复 |
| 求解退化 | 不能只平移或绕同一轴旋转，增加两个以上独立旋转轴和位置覆盖 |
| 独立测试偏差大 | 先检查板真实尺寸、法兰/TCP混用、板固定、型号/序列号、FK、分辨率 |
| 近距离PnP翻转 | 增加板倾角/成像面积/清晰度；歧义解会被拒绝，停止输出比使用跳变位姿可靠 |
| INCONSISTENT | 检查ETH矩阵方向、EIH链、同一物理目标及坐标轴、静态场景/时间差 |
| HOLD/IK失败 | 查看servo/status，检查工作空间、可达性、法兰朝向和关节裕度，不要放宽到无边界 |
| 相机断流 | camera节点记录错误并停止发布；定位超时后HOLD，恢复设备后重新启动节点 |

算法约定参考：[OpenCV 4.10 calib3d](https://docs.opencv.org/4.10.0/d9/d0c/group__calib3d.html)，
[ROS 2 Humble tf2 时间](https://docs.ros.org/en/humble/Tutorials/Intermediate/Tf2/Learning-About-Tf2-And-Time-Py.html)。
