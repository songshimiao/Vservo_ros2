# 接口、坐标系、数据和扩展

## 节点与接口

| 可执行文件 | 输入 | 输出/服务 |
|---|---|---|
| camera（eih/eth命名空间） | Orbbec彩色流、serial、intrinsics | `/<role>/image_raw`、`camera_info`、`metadata` |
| calibration（role命名空间） | 图像、内参/身份元数据、handeye模式下的TF | `/<role>/calibration/capture`、`solve`（Trigger） |
| detector（role命名空间） | 对应图像/CameraInfo/metadata | `/<role>/target_pose`（PoseWithCovarianceStamped）、`target_visibility`（String JSON）、`detector_status` |
| robot_bridge | SDK、可选手眼JSON、`/servo/desired_flange_pose`（完整目标）、`/servo/next_flange_pose`（旧接口） | `/robot/joint_states`、`/tf`、`/tf_static`、`/robot/status`、`/robot/speed_status`、`/robot_bridge/arm`（SetBool） |
| localizer | 两路 target_pose、图像时间的 TF | `/localization/target_pose`（PoseStamped，base）、`/localization/state`、`/localization/diagnostics` |
| servo | 对应粗精阶段的目标、状态、TF、EIH 手眼 | `/servo/desired_flange_pose`、`/servo/next_flange_pose`（均 PoseStamped，base）、`/servo/status` |
| accuracy_recorder | 指定PoseStamped话题、可选独立参考 | `/accuracy_recorder/capture`（Trigger）、JSON |
| tools | 离线文件 | board / solve / check-intrinsics / check-handeye / accuracy 子命令 |

图像QoS为sensor_data（best effort，volatile），图像处理不会依赖所有帧必达。
CameraInfo与metadata为reliable/transient_local/depth1，后启动的订阅者能取到参数。
目标话题reliable、depth5；微步depth1，最大年龄检查阻止处理积压命令。

Web `/api/image?role=eih&variant=servo`（ETH 同理）返回 ID42 坐标轴预览；`raw` 与标定 `overlay` 保留。RosLink 订阅各路 CameraInfo 和 target_pose，保存最多 12 帧/0.4 s 原图历史，按原始时间戳、frame_id、尺寸匹配。只有 0.3 s 内观测且 detector_status 为 TRACKING aruco_42 时显示轴。X/Y/Z 为红/绿/蓝，+Z 指入标记，轴长 0.04 m。绘制与 JPEG 在 Web 预览线程执行，不重新检测；失效或无匹配时回到原图，HTTP 输出再做一次时效检查，避免残留旧轴。

## 坐标和时间

当前目标选择为 `selection_policy: first_seen`。首次获得目标的相机保持主导，失效时才切换到另一台。ETH 主导时输出 COARSE / eth，EIH 主导时输出 FINE / eih，两路均失效输出 HOLD。此策略下双路偏差仅用于诊断，两种来源的法兰目标距离均使用 `fine_distance_m`（以实际 control.yaml 为准，本次现场为 0.20 m）。`eth_primary`、`handoff` 保留为历史可选策略。

机器人桥将全部已校验的手眼变换一次发布为完整 TFMessage，确保 `/tf_static` 的晚加入订阅者也能获得 EIH 与 ETH 两路。检测器 `target_visibility` 包含 frame_id、原图 stamp_ns、visible、target_id、reason。明确丢失帧作废该时刻及之前的相机观测，下一定位周期可直接交接；新鲜观测不受更旧丢失消息影响，旧位姿也不能复活已失效的帧。无消息仍用 max_age_s 过滤。

Localizer 对有效观测等待图像时刻 TF 的情况发布 WAITING_TF，机器人等待并清除双路丢失计时，不启动复位。只有两路都无有效目标才为 HOLD。diagnostics 新增 cameras.eih / cameras.eth，含 visible、localized、tf_ready、pending、observation_age_s、base_age_s、error。Web 显示每路目标定位/TF状态；执行前的 IK、限位和时效检查继续生效。

机器人桥新增 `auto_start` 参数，Web 运动监控启动时传 true。`/robot/servo_state` 为可靠、持久 JSON，包含 `enabled`、`drive_armed`、`mode`、`fault`、`reason`、`home_joint_deg`。视觉丢失会在 `target_loss_home_delay_s` 后执行受限 ServoJ 复位。复位完成保持请求并等待目标。`/robot_bridge/arm` 的 true 开启持续请求，false 关闭请求并结束运动。

当前关节速度上限 2 rad/s，`speed_scale` 为 0.1–1.0。复位角度为 `[90, -110, 110, -180, -90, 0]` 度，配置项为 `home_joint_deg`。实际控制周期超时、定位心跳超时、控制器错误、关节跟随误差或越界时撤销会话并发布故障，需处理原因后人工恢复。

定位心跳每 50 ms 发布，桥接使用独立心跳互斥回调组，ROS 执行器为 3 线程。SDK 由独立控制线程调度，数值 IK 放在单独 spawn 进程，避免 executor 队列与 Python GIL 争用影响控制。心跳接收不随 SDK 使能等待而阻塞，接收状态与命令快照用锁同步。0.5 s 心跳超时保护保持生效，使能返回后发送第一条 ServoJ 前也会重查。`/robot/servo_state` 另含 `localization_state`、`localization_age_s`（未收到时为 null）、`localization_timeout_s`，故障文本带实际超时时长。

控制名义周期为 10 ms，SDK 调用与人工启停串行，错过时隙不补发积压。watchdog 检查距上次成功 ServoJ 应答的间隔，并在 SDK 调用前后检查；指令间隔或单次 ServoJ 耗时超过 50 ms 时停止。启动使能耗时单独记录，发出第一条位置指令前重新检查心跳/目标。TF/关节反馈最多 50 Hz，普通机器人状态 10 Hz，故障立即发布。IK 等待最多 200 ms，忙时不重复排队，超时/不可达不使用旧观测冒充新目标。

复位 81 点预检查也在后台规划进程执行，与 IK 通过 planner_lock 共用单工作进程，控制线程不等待结果。`BRAKING_FOR_HOME` 表示按关节加速度减速，`PREPARING_HOME` 表示后台检查或等待规划进程，`RETURNING_HOME` 才开始复位。准备期间已经使能的 SDK 继续保持受限指令。结果使用前若当前位置偏离检查起点超过 0.005 rad 则重新检查；目标重捕获和人工停止作废尚未执行的复位结果，已开始的复位继续完整执行。路径和执行逐步限位检查保留。

`/robot/servo_state` 的 `control_timing` 包含 `period_ms`（循环起始间隔）、`command_gap_ms`（成功 SDK 应答间隔/空窗）、`work_ms`、`servoj_ms`、`enable_ms`、`timeout_ms`、`stage`。`fault_timing` 为 null 或冻结的故障快照，另含 `current_work_ms`。Web 优先显示故障快照，完整错误含指令间隔与 SDK 耗时，用于区分计算、调度和通信问题。

所有矩阵记为 `parent_T_child`，左乘列向量将child坐标转到parent。
距离m，旋转计算rad，机器人SDK关节输入输出deg，报告平移mm/旋转deg。
四元数ROS顺序xyzw。`base`为机器人基座；`flange`是tool0法兰，不能替换为有偏置的TCP。

TF树：

```text
base
├── flange                     动态：关节角 + FR5 MDH
│   └── eih_optical_frame       静态：EIH手眼
└── eth_optical_frame           静态：ETH手眼
```

相机光学坐标x右/y下/z前，不额外虚构camera_link旋转。
没有可用手眼文件时，相机frame存在于图像头但不接入TF树；禁止发布单位阵占位。
相机帧使用SDK返回图像后的主机接收时刻，不是曝光硬件时刻。两路无硬同步，运动场景有USB/曝光延迟误差。
校准必须静止；高速动态双目融合需后续实现设备时间映射、曝光同步或时延标定。
机械臂TF以一次RPC读取的开始/结束中点时间标记，读取耗时>80ms拒绝。
EIH目标变换严格查询图像时间，不使用latest TF；每路最多缓存10组待变换观测，
等待后续机器人状态帧再按原图像时间重试，超过0.3秒的观测丢弃。

定位节点发布 `/localization/coarse_target_pose` 或 `/localization/fine_target_pose` 给伺服节点，对应 ETH 和 EIH，避免切换阶段时误用上一步的目标。`/localization/target_pose` 继续输出当前选中的位姿，供 Web 和精度记录器订阅。`/localization/diagnostics` 给出 `source`、`reason`、`handoff_count` 和 `pair_status`。交接只用 ETH 粗定位的时间戳作为时限依据。粗定位目标按原观测时效检查，精定位目标始终来自新鲜 EIH 观测。

在旧 `handoff` 策略下，`require_pair_agreement` 默认 false。EIH 接管后可在 `target_loss_timeout_s` 内重新确认，ETH 回接前保留 `reacquire_delay_s` 等待。

Web `/api/speed` POST 接受数值 `percent`（10–100），以及可选 `linear_mm_s`、`angular_deg_s`、`joint_accel_rad_s2`。运行中通过 `/robot_bridge/set_parameters_atomically` 一次设置 double 参数 `speed_scale`、`linear_speed_m_s`、`angular_speed_rad_s`、`max_joint_accel_rad_s2`。线速度和角速度须大于 0，分别不超过 0.2 m/s 和 π/3 rad/s，加速度须在 (0, 2] rad/s²；ROS 侧再次验证，任一无效则整组拒绝。仅传 percent 的旧客户端继续可用。

`/robot/speed_status` 为 reliable/transient_local JSON，包含 `percent`、倍率后的 `max_joint_speed_rad_s`、独立的 `max_joint_accel_rad_s2`、倍率前 `linear_speed_m_s` / `angular_speed_rad_s`，以及倍率后 `effective_linear_mm_s` / `effective_angular_deg_s`。Web 展示的生效值是配置上限，减速按加速度限制逐步进行。

`/servo/desired_flange_pose` 每 20 ms 发布完整期望法兰位姿，保留原视觉时间戳。桥接独立回调组完成 IK，100 Hz SDK 定时器按关节制动距离、关节速度/加速度和模型预测的笛卡尔速度生成每一步指令。限幅同样用于复位。相机模式切换或停止时丢弃正在计算的旧 IK 结果。完整目标超时、不可达或越界时等待有效指令，持续请求保留；控制故障仍停止。目标 IK 解直接用于受限关节推进，中间路径按模型逐步检查工作空间，未实现障碍物规划。

旧 `/servo/next_flange_pose` 仍提供 1 mm / 0.01 rad 乘倍率的微步预览，保留旧接口的 5 mm / 3° 位姿增量与 5° IK 分支检查。桥接一旦收到完整目标流便不再使用微步流，避免两个来源交替覆盖。完整目标使用限速连续指令，目标本身不受旧微步距离门槛限制。

当前 `control.yaml` 选用 `tracking_frame: flange`，粗定位距离 0.30 m，精定位距离 0.20 m；first_seen 下两路都使用精定位距离。期望法兰位姿为 `base_T_target × target_T_flange`。用 `tracking_frame: camera` 可选择原相机参考点，期望法兰位姿按相机手眼逆矩阵换算。

## 标定数据

会话 `samples.json` 包含schema_version、role、mode、board、camera（型号/序列号/安装方式/分辨率）、
intrinsics、image_size、samples。每组保存PNG、stamp_ns、object_points、image_points、corner_ids；
handeye模式额外保存base_T_flange、camera_T_board与重投影误差。

内参输出camera_matrix、dist_coeffs、image_size、source、validated、train_indices、heldout_indices、
train_rms_px、heldout_rms_px、camera、board。5参数Brown畸变求解；SDK8参数rational内参仅供首次启动。
不自动缩放内参，不复用另一序列号结果。当前不支持鱼眼/逆Brown模型。

手眼输出mode=eih/eth、parent_frame、child_frame、matrix、units=m、method=PARK、
reference_matrix、旋转激励奇异值、训练和留出报告。EIH reference为base_T_board；ETH为flange_T_board。
数据以原子替换保存。失败会话保留原图，求解失败不写出合格标定。
旧工程 `cam_T_gripper_or_base` 字段方向名称有歧义，新版不直接读取；必须重新采样或人工核对转换并独立验证。

## 伺服目标和 YOLO 后续接入

Web 监控启动时使用 `target_id:=aruco_42`。命令行可用 `visual_servo.launch.py` 的 `target_id:=aruco_<ID>` 和 `aruco_marker_m:=0.080` 参数显式选择。内置单标记检测器使用 `DICT_4X4_50`。四个像素角点以标记外边长为尺度，通过 `SOLVEPNP_IPPE_SQUARE` 求解，再将坐标系旋转为 +X 向右、+Y 向下、+Z 指入标记，原点为中心。两台相机使用相同 ID 和边长。 [OpenCV PnP 参考](https://docs.opencv.org/4.11.0/d9/d0c/group__calib3d.html)

`vservo_ros2.yolo_adapter:YoloPoseAdapter` 是明确抛出NotImplementedError的扩展契约，未附带权重或假检测结果。
替换检测后端时，实现独立可导入的 Python 类：

```python
from vservo_ros2.board import Observation

class MyYoloMetricPose:
    def detect(self, bgr, K, D):
        # 检测/跟踪同一物理目标，获取米制位置和完整姿态。
        # 可用已知CAD的关键点PnP，或彩深对齐+几何拟合等。
        # 缺失、歧义或质量不足时raise ValueError，不返回上一帧。
        return Observation(camera_T_target=T, covariance=cov6x6,
                           target_id='part_A', reprojection_px=rms_px)
```

启动完整系统时加：

```bash
eih_plugin:=my_package.yolo_pose:MyYoloMetricPose \
eth_plugin:=my_package.yolo_pose:MyYoloMetricPose target_id:=part_A
```

类无参构造，权重/阈值等配置由插件内部或自有包管理；推荐在插件内显式记录版本与模型校验和。
插件输入为未缩放原始BGR与该分辨率K/D；如果YOLO内部letterbox，输出关键点必须变换回原图像素。
covariance是同一camera frame下 `[x,y,z,rx,ry,rz]` 的6×6矩阵，单位m²/rad²，需对称半正定，
应通过独立误差数据估计。当前ChArUco默认协方差是保守名义值，不宣称统计标定精度。
两路必须返回同一物理物体的同一原点/轴向；多个同类物体须做身份关联，不能只匹配类别名。

YOLO 2D框本身不提供米制深度与姿态。要采用对齐深度，应扩展camera节点发布depth与对齐/外参信息；
当前只发布彩色，不会从未对齐的depth像素直接取z。不能把2D框中心+固定深度冒充完整6D定位。
对对称物体需定义允许的姿态等价关系或改用位置控制器，当前PBVS要求完整、唯一方向。

## 与原工程的关系

`vendor/camera_stream.py` 从旧工程复制，保留Gemini305/335按型号及序列号选择、SDK畸变顺序转换和资源释放。
`vendor/fairino_dh_params.py` 保留原工程DH来源注释；本包按Craig MDH实现FK和带边界的数值IK。
SDK不重新分发，运行时加载用户现有Robot.py，桥接已按该SDK的 `ServoJ(joint_pos, axisPos, ..., cmdT)` 适配。
新版未直接启动旧PBVS进程；相机、检测、定位、控制各有ROS节点与时间戳契约。
